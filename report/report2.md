# Отчет по домашнему заданию "Конечный автомат для поиска подстроки. Префикс-функция"

## Реализация

### Класс конечного автомата

Конечный автомат реализован в виде шаблонного класса `KMPAutomaton<PrefixMode>` ([KMPAutomaton.h](../headers/KMPAutomaton.h)), где параметр шаблона определяет способ вычисления префикс-функции:

### Варианты префикс-функции

| Вариант | Сложность | Принцип работы |
|---------|-----------|----------------|
| **Медленный** | O(m³) | Перебор всех возможных суффиксов для каждой позиции |
| **Быстрый** | O(m) | Использование ранее вычисленных значений π |

Код префикс-функции реализован внутри класса: сделаны две полные специализации - SLOW и FAST, в соответствии с заданием

### Таблица переходов (сжатая)

В отличие от полной таблицы на 256 символов, используется **сжатое представление** — `std::unordered_map<char, size_t>` для каждого состояния. Хранятся только переходы, ведущие в ненулевое состояние. Default-переход (символ не найден в таблице) означает переход в состояние 0.

## Анализ результатов

### 1. Малые объемы данных (до 100 байт)

На малых текстах все алгоритмы показывают сопоставимые результаты. Небольшое преимущество классического КМП (0 мкс против 1-2 мкс у автомата) объясняется отсутствием накладных расходов на хранение и обращение к таблице переходов.

### 2. Большие объемы данных (500000 байт)

На большом тексте разница становится заметной:

| Алгоритм | Время (мкс) | Относительная скорость |
|----------|-------------|------------------------|
| КМП (классический) | 872 | **базовый** |
| Автомат (FAST) | 2060 | ~2.4x медленнее |
| Автомат (SLOW) | 2175 | ~2.5x медленнее |

### 3. Почему автомат медленнее классического КМП?

Хотя оба подхода используют одинаковую префикс-функцию, автомат имеет дополнительные накладные расходы:

- **Таблица переходов**: поиск в `unordered_map` на каждом шаге (хотя и O(1) в среднем, но дороже прямого доступа к массиву)
- **Память**: сжатая таблица экономит память, но добавляет косвенность
- **Построение**: требуется дополнительное время на построение таблицы (хотя в наших замерах оно включено в общее время)

### 4. Медленная vs быстрая префикс-функция

На большом тексте разница между SLOW (2175 мкс) и FAST (2060 мкс) составляет всего ~5%, потому что:
- Построение таблицы переходов занимает O(m·|Σ|) времени
- Для шаблона длиной 99 байт вклад префикс-функции в общее время невелик

Однако при **многократном перестроении автомата** (например, для разных шаблонов) разница стала бы драматической — медленный вариант O(m³) против быстрого O(m).

## Выводы

1. **Конечный автомат успешно реализован** и демонстрирует корректную работу. Пошаговое прохождение наглядно показывает, как автомат распознаёт шаблон в тексте.

2. **Сжатая таблица переходов** (на основе `unordered_map`) — правильный выбор для учебного проекта. Она экономит память и наглядно показывает, какие символы реально влияют на переходы.

3. **Быстрая префикс-функция** (линейная) несомненно предпочтительнее медленной (кубической). Разница в производительности — тысячи раз даже на коротких шаблонах.

4. **Классический КМП** (без явного автомата) оказался быстрее автоматной версии:
   - Нет накладных расходов на таблицу переходов
   - Прямой доступ к массиву вместо поиска в `unordered_map`
   - Меньший расход памяти

5. **Практическая рекомендация**: 
   - Для понимания принципов работы — автомат отлично подходит
   - Для production-кода — лучше использовать классическую реализацию КМП
